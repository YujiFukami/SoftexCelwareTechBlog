<Term>Google Apps Script</Term>のWebアプリは、URLが1つ（`/exec`）しかありません。次のような作りは危険です。

- スタッフ用のURLの後ろを消すと、管理用の画面が開く
- パスワードをシートやスクリプトプロパティにそのまま置き、編集者に丸見えになる
- 毎回パスワードを送る作りで、画面がパスワードを持ち続ける

これらを避けるための作り方を、5つにまとめます。

## 1. doGetで振り分け、素の/execでは何も出さない

~~~js
function doGet(e) {
  var p = e.parameter || {};
  if (p.s) { /* スタッフのトークンを照合し、スタッフ用の画面を返す */ }
  if (p.a && p.a === PropertiesService.getScriptProperties().getProperty("ADMIN_KEY")) {
    /* 管理用の画面を返す */
  }
  return HtmlService.createHtmlOutput("URL が正しくありません。");
}
~~~

管理用のキーは推測できない24文字にしてスクリプトプロパティに置き、メニューから表示と作り直しができるようにします。

## 2. パスワードはハッシュだけを保存する

「人ごとのソルト＋パスワード＋ペッパー（スクリプトプロパティに保存）」を、`Utilities.computeDigest`のSHA-256で数百回繰り返してハッシュにし、base64にしてシートに保存します。パスワードそのものは保存しません。

GASにはbcryptなどのパスワード専用の仕組みがないので、繰り返しのハッシュで代用しています。パスワード自体は、推測されにくい長さにしてもらいます。

- 忘れたら、管理者が仮パスワードを発行する（画面に1回だけ表示）。初回のログインで変更させる
- 5回失敗したら15分ロックする。失敗回数とロックの期限もシートに保存する

## 3. ログイン後は通行証を使う

ログインに成功したら、ランダムな40文字の通行証を作り、`CacheService.getScriptCache().put("sess:" + tok, JSON, 21600)`で保存します。画面は通行証をsessionStorageに持ち、`google.script.run`で呼ぶすべてのAPIの第1引数で送ります。

サーバーは毎回、通行証からだれか、どの権限かを引きます。権限は毎回シートから読むので、管理者が権限を変えるとすぐに反映されます。

**読み取り専用のAPIも、通行証を必須にします**。スタッフ用の画面から、開発者ツールで管理用のAPIを呼ばれないようにするためです。

## 4. 権限はサーバーで判定する

登録、変更、削除、「担当の利用者だけ」などの権限を、人ごとの列で持ちます。触れるのは、自分の行と担当の利用者の行だけにします。画面でボタンを隠すだけでは不十分で、サーバーで毎回判定します。

## 5. 行を消さずに残す（ソフト削除）

行は消さず、「削除済み」「削除した人」「日時」を記録します。読み込むときに有効な行と削除済みの行に分け、集計や通知には有効な行だけを渡します。管理者だけが、元に戻す操作と、完全に消す操作をできるようにします。変更の記録には、変更前と変更後を残します。

## 手元で試してから反映する

Node.jsの`vm`で`.gs`を読み込み、SpreadsheetApp、CacheService、`Utilities.computeDigest`などを真似た偽物で、ログイン、ロック、権限、URLの振り分けを試してから反映すると安心です。

- `computeDigest`は符号付きのバイト配列（-128〜127）を返すので、真似るときも合わせる
- `vm`の中で作った配列は、`assert.deepEqual`では一致しないことがある。`JSON.stringify`で比べる
