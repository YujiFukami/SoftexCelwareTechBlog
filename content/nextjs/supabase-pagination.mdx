## はじめに

<Term>Supabase</Term>でデータを取得していて、「あれ、1000件ちょうどしか返ってこない...？」と首をかしげた経験はありませんか？

実は<Term>Supabase</Term>の `.select()` にはデフォルトで**最大1000行**という取得制限があります。普段の画面表示では問題になりませんが、作業履歴や出退勤記録をExcelにエクスポートしたいとき、全件取得できないと困りますよね。

この記事では、`.range()` を使ったページネーションで全データを確実に取得するパターンを紹介します。

## こんな場面で使えます

- 設定画面から全作業履歴をExcelエクスポートする
- 全出退勤記録を一括ダウンロードする
- 集計画面で長期間（数千件以上）のデータをまとめて取得する
- 1000件を超える可能性があるテーブルからデータを読み出す場面全般

## 実装コード

1000件ずつデータを取得し、すべてを結合して返す関数です。

```typescript
const PAGE_SIZE = 1000

async function fetchAll<T>(
  query: (from: number, to: number) => PromiseLike<{
    data: T[] | null;
    error: { message: string } | null;
  }>
): Promise<T[]> {
  const all: T[] = []
  let offset = 0

  while (true) {
    const { data, error } = await query(offset, offset + PAGE_SIZE - 1)

    if (error) throw error
    if (!data || data.length === 0) break

    all.push(...data)
    if (data.length < PAGE_SIZE) break  // 最終ページ
    offset += PAGE_SIZE
  }

  return all
}
```

### コードのポイント

- **`.range(from, to)`** でオフセットベースのページネーションを行います。`from` と `to` はどちらも**inclusive（含む）**なので、`offset + PAGE_SIZE - 1` とする点に注意してください
- **最終ページの判定**: 取得件数が `PAGE_SIZE` 未満なら、それが最後のページです。これにより余計なクエリの発行を防ぎます
- **一意キーまで順序を指定する**: 日時が同じ行は主キーでも並べ、ページ境界で順序が曖昧にならないようにします
- **途中エラーを握りつぶさない**: エラー時に`break`すると、途中までの件数で集計・出力してしまいます。失敗として呼び出し元へ返します

## 使い方・カスタマイズ

### テーブルやフィルタ条件を変える

取得条件と並び順は呼び出し側で指定します。各ページで同じ条件を使い、毎回新しいクエリを作ります。

### ページサイズを変える

`PAGE_SIZE`はサーバー側の最大取得行数以下にします。1000行は既定値で、プロジェクトのAPI設定により変わる場合があります。1000を要求して上限500の応答を受けると、最終ページと誤判定するため、設定値との整合が必要です。

### 汎用的に使う

たとえば作業履歴を日時と主キーで並べて取得します。期間の絞り込みがあれば、同じクエリに追加します。

```typescript
const histories = await fetchAll((from, to) =>
  supabase.from('work_history').select('*')
    .eq('user_id', userId)
    .order('started_at', { ascending: true })
    .order('history_id', { ascending: true })
    .range(from, to)
)
```

## 注意点・ハマりポイント

- **RLS（Row Level Security）が有効な場合**: `.eq('user_id', userId)` のフィルタはRLSと重複しますが、コードの意図を明確にするために明示しておくのがおすすめです
- **大量データの場合のメモリ**: 全件をメモリに溜め込むため、数十万件規模ではブラウザのメモリ不足に注意してください。そのような場合はサーバーサイドで処理することを検討しましょう
- **`range()` の引数は inclusive**: `range(0, 999)` で1000件取得です。`range(0, 1000)` とすると1001件になるので注意してください
- **取得中の挿入・削除**: 一意な順序があっても、別リクエストの間に行が増減するとオフセットがずれます。厳密なスナップショットが必要ならDB側での集計・エクスポートやキーセット方式を検討します
- **境界件数を試す**: 0件、999件、1000件、1001件、同一日時の行、2ページ目のエラーを確認します。件数がちょうどページサイズの倍数なら、最後に空ページの取得が1回必要です

## まとめ

- <Term>Supabase</Term>の取得行数には、既定1000行のサーバー側上限がある
- `.range()` を使ったループで**全件取得のページネーション**が実装できる
- 一意な`order()`、途中エラーの通知、`PAGE_SIZE - 1`の計算を忘れずに
