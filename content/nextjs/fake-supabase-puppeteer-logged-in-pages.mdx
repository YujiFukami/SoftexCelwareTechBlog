<Term>Next.js</Term>と<Term>Supabase</Term>（`@supabase/ssr`）で作ったアプリで、ログイン後の画面のスマホ表示の崩れなどを、手元で確かめたいことがあります。しかし、本物のアカウントでのログインが必要で、本番のデータベースに検証用のデータを作りたくもありません。

認証のミドルウェアがサーバー側で`getUser()`を呼ぶので、ブラウザ側の通信を差し替えるだけでは、ログイン後の画面に進めません。そこで、サーバーごと差し替えられるように、偽のSupabaseを立てます。

## 1. 偽のSupabaseを立てる

架空のデータを返す小さなHTTPサーバーを、`localhost:54321`で動かします。

| リクエスト | 返すもの |
|---|---|
| `GET /auth/v1/user` | 架空のユーザー |
| `GET /rest/v1/<テーブル>` | 架空の行。`Accept: application/vnd.pgrst.object+json`のときは1件のオブジェクト |
| `POST /rest/v1/rpc/<関数>` | 期待する戻り値。受け取った内容を記録すると、何が送られたかも確認できる |

CORSのヘッダーと、OPTIONSへの204の応答も忘れずに返します。

## 2. 偽のSupabaseを向いた開発サーバーを起動する

`NEXT_PUBLIC_SUPABASE_URL=http://localhost:54321`を付けて`next dev`を起動します。コマンドで指定した環境変数は、`.env.local`より優先されます。本番用のビルド結果を上書きしないよう、`build`ではなく`dev`を使います。

## 3. セッションのCookieを入れてから開く

<Term>Puppeteer</Term>で、`@supabase/ssr`が読むセッションのCookieを直接入れてから、ページを開きます。

~~~js
const session = {
  access_token: "mock-token", refresh_token: "mock-refresh", token_type: "bearer",
  expires_in: 3600, expires_at: Math.floor(Date.now() / 1000) + 3600,
  user: { id: "11111111-1111-1111-1111-111111111111", aud: "authenticated",
          role: "authenticated", email: "demo@example.com" },
};

// Cookie名は sb-<URLのホスト名の先頭>-auth-token。localhostなら sb-localhost-auth-token
await page.setCookie({
  name: "sb-localhost-auth-token",
  value: "base64-" + Buffer.from(JSON.stringify(session)).toString("base64url"),
  domain: "localhost",
  path: "/",
});
await page.setViewport({ width: 390, height: 844, isMobile: true, hasTouch: true });
await page.goto("http://localhost:3000/dashboard", { waitUntil: "networkidle0" });
~~~

## 4. はみ出しは「表とその枠」でも測る

~~~js
const t = document.querySelector("table");
const fits = t.scrollWidth <= t.parentElement.clientWidth;
~~~

枠に`overflow-hidden`が付いていると、ページ全体の横のはみ出し（`documentElement.scrollWidth`）は検出されません。中身だけが切れて操作できない状態になります。表の幅と枠の幅を比べないと見逃します。実際に、一覧表のスマホ表示でこの問題が起きていました。

## 注意点

- **見えている要素を操作する**：スマホ用とPC用で同じ入力欄を2つ持ち、片方を`hidden md:block`で隠す作りの場合、`page.$()`は隠れている方を拾うことがあります。`offsetParent !== null`で見えている要素を選んでから操作します
- **偽サーバーは状態を持つ**：同じ操作を2回流すと、前回の結果が残ります。テストのたびに再起動するか、別の行を使います
- **プロセスを必ず止める**：Windowsでは開発サーバーの子プロセスが残り、次の`npm ci`が`EPERM`で失敗することがあります
