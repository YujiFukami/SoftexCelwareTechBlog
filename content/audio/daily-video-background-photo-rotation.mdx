<Term>Python</Term>で毎日自動で作るニュース動画で、背景の写真が前日とほとんど同じになりました。「28日以内に使った写真は使わない」という決まりを入れていたのに、です。原因は2つありました。

1. **作り直しのたびに、使わなかった版の写真まで「使った」と記録していた**：1日に3〜4回作り直すと、1回の放送で25〜32枚を消費し、手持ちの209枚のうち201枚が「使用済み」になっていました
2. **使える写真が尽きたときの選び方が逆だった**：並べ替えの基準に「最後に使った日（文字列）」を入れて`max()`で選んでいたため、**一番最近使った写真**が選ばれていました

## 1. 記録は「日付×用途」ごとに、最後の版で置き換える

~~~json
{"log": {"2026-11-24": {"video": ["a", "b"], "story": ["c"], "shorts": ["d"]}}}
~~~

- 読むときは、今日の自分の用途の記録を除いて「写真ID→最後に使った日」を作る（作り直し中の、自分の前の版を数えない）
- 保存は`log[今日][用途] = 今回使った写真`の上書きにする。何回作り直しても、その日の記録は最後の版だけになる
- 用途（本編、ストーリーズ、ショート）を分けておくと、片方を作り直しても、他方の記録が消えない

~~~python
def used_map(log, skip=None):
    used = {}
    for day in sorted(log):
        for purpose, ids in log[day].items():
            if skip and (day, purpose) == skip:
                continue
            for pid in ids:
                used[pid] = day
    return used
~~~

## 2. 尽きたら「一番前に使ったもの」から選ぶ

~~~python
def _age(p):  # 最後に使ってからの日数（未使用は大きな値）
    last = used.get(p["id"])
    return (today - date.fromisoformat(last)).days if last else 10**6

# 使える写真がある段：話題に合う数→季節→古さ
key = (hits, season_ok, _age(p))
# 使用済みから選ぶ段：古さ（週単位）→話題に合う数
key = (_age(p) // 7, hits, season_ok)
~~~

古さを週単位にすると、「同じくらい前に使った写真」の中で、話題に合うものを選べます。

`max()`の基準に日付の文字列を入れると、新しい日付ほど大きいので、最近使ったものが選ばれます。**古いものを選びたいなら、経過日数（大きいほど古い）を使います。**

## 3. 候補は段に分けて、最初に空でない段から選ぶ

1. 28日以内に使っていない、かつ季節が合う
2. 季節が合う（使用済みでも）
3. 28日以内に使っていない（季節は違う）
4. 残り全部

`next(c for c in candidates if c)`で、最初に空でない段から選びます。11月に桜の写真が出るより、少し前に使った秋の写真のほうが自然です。

## 4. 壊れた記録は、公開した回の制作記録から作り直す

壊れた記録は捨てずに、実際に公開した回の制作記録（場面ごとの写真ID）から作り直しました。作り直しで余計に「使用済み」になっていた写真が戻り、使用済みは201枚から111枚になりました。

## ポイント

- 「使ったら記録する」処理は、**作り直しや試作で何回呼ばれるか**を考える。記録は「確定した版」で置き換える形にする
- 事件や事故の話題で、場所の分かる写真を使うと、現場と誤解されるおそれがある。空や海など、地名の分からない写真だけを集めた中立の候補を用意し、道路や町並みが写る写真は目で見て除外する
