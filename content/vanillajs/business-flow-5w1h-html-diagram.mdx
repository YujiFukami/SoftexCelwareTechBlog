お客様の業務が「複数の担当者×複数の<Term>Excel</Term>×紙や外部システム」に分かれているとき、どこからどこへ同じ値が転記されているのかを、打ち合わせの前に正確に把握したいことがあります。

自分で描いた矢印だらけの図は、線が交差して読めず、解釈が正しいかも確かめにくくなります。箱を自由に配置してSVGの曲線でつなぐネットワーク図も試しましたが、線とラベルが重なって読めませんでした。

そこで、HTML 1枚に4種類の図と表をまとめる形にしました。

## 1. 作業の一覧を1つだけ持つ

すべての図と表を、作業の一覧（配列）1つから作ります。解釈を直すときは、1か所を直すだけで済みます。

作業ごとに持つ項目は、id、番号、だれが、時間帯、確度、いつ、どこで、何を見て、どこへ、どうやって、お客様の原文、要確認の内容です。

## 2. 4種類の図を縦に並べる

- **時系列（スイムレーン）**：CSS gridで「だれ×時間帯」の表にする。依存関係（この作業が終わらないと次ができない）は、要素の位置を測ってSVGの点線の矢印で後から描く
- **データの流れ（流れごとに1行）**：自由配置をやめ、「出どころ→作業→ファイル→…」を左から右へ1行ずつ並べる。枝分かれは縦に積む。同じファイルには同じ色の丸を付けると、同じファイルが何行にも出てくる（何度も入力している）ことが一目で分かる。転記やコピー＆ペーストは赤の破線にする
- **5W1Hの一覧表**
- **同じ値の行き先のマトリクス**：行がデータ項目、列がファイル（シート）、セルが作業番号（入力、転記、自動、要確認）。右端に手入力の回数を出し、2回以上を赤字にする

データの流れを1行ずつ並べる形にしたことで、線の交差がなくなり、一目で読めるようになりました。

~~~js
const NB = (k, t, s = "") => ({ node: k, t, s });          // 箱（入力元、紙、ファイルなど）
const AR = (s, t, k = "in") => ({ arrow: s, t, k });        // 矢印（作業id、in/copy/auto）
const BR = (...rows) => ({ branch: rows });                // 枝分かれ

const FLOWS = [{ title: "④ 計測値", chain: [
  NB("paper", "記入用紙"), AR("C5", "手入力"), NB("f05", "05 計算"),
  BR([AR("C5", "合計", "copy"), NB("f01", "01 日報")],
     [AR("C6", "内訳", "copy"), NB("f02", "02 内訳表"), AR("C4", "翌日コピペ", "copy"), NB("f04", "04 集計")]),
]}];

function chainHtml(items) {
  return items.map((it) => it.node ? nodeHtml(it)
    : ("arrow" in it) ? arrowHtml(it)
    : `<div class="fbr">${it.branch.map((r) => `<div class="fbrow">${chainHtml(r)}</div>`).join("")}</div>`
  ).join("");
}
~~~

~~~css
.fchain { display: flex; align-items: center; flex-wrap: nowrap; }
.fa i { border-top: 2.5px solid; position: relative; }   /* 矢印の軸 */
.fa i::after { content: ""; position: absolute; right: -3px; top: -7.5px;
  border: 6px solid transparent; border-left: 9px solid; }  /* 矢じり */
.fa.copy i { border-top-style: dashed; border-color: #c62828; }
.fbr { display: flex; flex-direction: column; gap: 8px; border-left: 2.5px solid #c9ccbf; }
~~~

## 3. 確度を必ず示す

作業ごとに、「確認済（お客様の文面どおり）」「推定（自分の解釈）」「要確認（打ち合わせで聞く）」の3段階のタグを付けます。時間帯も、文面にあるもの以外は推定と明記します。

どの図のカードや行を押しても、同じ作業を全部の図で強調し、5W1Hと**お客様の原文**を横に表示します。原文を並べて見ることで、自分の解釈が文面と合っているかをその場で確かめられます。

最後に「自分の理解との照合」欄を置き、合っていること、直したほうがよいこと、打ち合わせで聞くことの3列にまとめます。

## 4. 色は「場所」にだけ使う

色は、入力元と入力先の「場所」（各Excel、外部システム、紙、現場）にだけ割り当て、すべての図で同じ色にそろえました。紙は破線、Excelとシステムは実線にします。担当者には色を使わず、濃い色のラベルにします。人と場所の両方に色を使うと、どちらの色か分からなくなるためです。

## 5. 実際のExcelの画面に入力箇所の枠を重ねる

場所を押すと、実際のExcelの画面に入力箇所の赤枠を重ねて表示するようにしました。

ExcelをCOMで操作して範囲を画像にし、同時に入力箇所のセル範囲の位置を「画像の中の割合（%）」で出しておきます。HTMLでは、画像の上に`position: absolute`の枠を割合で重ねるだけなので、どの拡大率でもずれません。結合セルも、`Left`、`Top`、`Width`、`Height`でそのまま位置を取れます。

枠の種類は、赤の実線（ここに入力）、青の破線（ここの値を見て別の所へ写す）、紫の破線（だれが入れるか要確認）、灰色（式で自動）に分けました。

## 注意点

- お客様の資料をもとにした把握用の資料なので、公開せず、ローカルのHTMLファイルで持つ
- `file://`で開く場合、データは`fetch`ではなく`<script src>`で読み込む
- 横スクロールの枠の中では、表の見出しの`position: sticky`が意図どおりに動かず、撮影で1行目を隠したので外した
