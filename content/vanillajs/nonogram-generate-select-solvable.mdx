画像やQRコードから<Term>ノノグラム</Term>（イラストロジック）の問題を作ると、答えが1つに決まらない、論理だけでは解き切れない問題になりやすくなります。「境界にランダムに黒マスを足す」「ノイズを足す」などの方法で後から直そうとしても、絵が崩れるだけで、解けるようにはなりませんでした。

## 直すより選ぶ

考え方を変えて、同じ見た目、同じ意味になる候補を数百通り作り、ソルバーで解ける割合を測って、最良のものを選ぶことにしました。

ソルバー（1列ずつの推理と、仮置きによる確認）は、30〜60マス四方なら1回25〜100ms程度です。数百通りを試しても、数秒で終わります。

## QRコードの場合

同じURLでも、次の組み合わせで模様が変わり、どれも正しく読めます。

- マスクのパターン（8種類）
- 誤り訂正のレベル（L、M、Q、H）
- URLの末尾に`#1`、`#2`などを付ける（開くページは同じ）

2026年11月の実測では、次のようになりました。

| URL | 通常の作り方（誤り訂正M、自動マスク） | 512通りから選ぶ |
|---|---|---|
| example.com | 99.0%まで解ける | 完全に解ける候補が92個 |
| 会社のサイト | 88.9% | 完全（15個） |
| GitHub Pagesのページ | 70.3% | 完全（13個） |
| Googleの検索URL | 18.6% | 完全（21個） |

選んだ候補は、必ずQRコードの読み取りライブラリ（jsQR）で読めることを確かめます。

## 画像の場合

しきい値（明るさの分位点35〜65%）、ならし（3×3の中央値）、穴埋め、孤立したマスの除去などの組み合わせを、80〜144通り試します。

- 写真6枚×5サイズの30ケース中、29ケースで、そのまま完全に解ける設定が見つかった
- 完全に解ける設定が複数あるときは、黒の割合が半分に近いものを選ぶと、絵が薄くならない
- **点描（ディザ）は避ける**：同じ写真で、解ける割合が4〜96%とばらつき、直すのにも多くの手間がかかった

## それでも残ったとき

- **ヒントマス**：最初から開けておくマスを足します。未確定のマスから16〜24個を試し、開けたときに決まるマスが一番増えるものを1つずつ足します。絵やQRコードを一切変えないのが利点です
- **目立たないマスの反転**：元画像の明るさがしきい値に近いマス（もともと白黒があいまいなマス）から順に、1つずつ反転して効果を確かめます

## アプリへの組み込み

探索の処理はWeb Workerで動かし、画面が固まらないようにしました。Workerを作れない環境（`file://`など）では、同じ関数を画面側で実行します。QRコードの読み取りライブラリはWorkerでだけ読み込むので、画面の初期表示は重くなりません。

探索で見つけた画像の設定は、そのまま画面の設定に反映し、同じ盤面を再現できるようにしています。

## つまずきどころ：QRコードの日本語が化ける

QRコード生成ライブラリ（qrcode-generator）の`addData(text, "Byte")`は、既定では文字コードの下位8ビットだけを使います。そのため、日本語を含む文字列のQRコードは、読むと文字化けします。

~~~js
qrcode.stringToBytes = qrcode.stringToBytesFuncs["UTF-8"];
~~~

この設定で直ります。読み取りライブラリで読み戻して、元の文字列と比べる確認を入れていたので気づけました。
