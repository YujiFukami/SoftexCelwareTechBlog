開発事例の記事を、文章と流れ図だけで書くと、どんな画面でどんな仕組みなのかが伝わりにくくなります。一方で、案件の録画や画面には、依頼者の名前、住所、メール、社名、地名が全面に映っていることが多く、そのままでは使えません。

<Term>Wix</Term>のブログで事例記事を作るときに使っている、画像の作り方を紹介します。

## 1. 要件定義で送った資料を探す

要件定義のときに依頼者へ送った仕様の資料（説明画像）を探します。説明の吹き出しや矢印が最初から入っているので、そのまま注釈付きの図として使えます。録画から画面を切り出すより早く、分かりやすい画像になります。

## 2. 個人情報の部分だけモザイクをかける

<Term>Pillow</Term>で、指定した範囲を縮小してから拡大し直します。

~~~python
from PIL import Image

def mosaic(img, x, y, w, h, block=16):
    x2, y2 = x + w, y + h
    part = img.crop((x, y, x2, y2))
    sw, sh = max(1, w // block), max(1, h // block)
    part = part.resize((sw, sh), Image.BILINEAR).resize((w, h), Image.NEAREST)
    img.paste(part, (x, y))
~~~

コマンドラインから`--box 左,上,幅,高さ`を複数指定できる形にしておくと、資料ごとに使い回せます。

## 3. 業種が分かる資料は、解説図に置き換える

品目、団体名、地名など、業種が特定される言葉が読めてしまう資料は使いません。代わりに、「クラスA」「区分1」などの一般的な言葉に置き換えた解説図をHTMLで書き、画像にします。見た目は共通のCSSでそろえます。

画面の画像には、タイトル、赤枠と番号、番号ごとの説明を付けて仕上げます。

## つまずきどころ

- **AIが見た画像の座標は縮小表示の座標**：画像を読み込んで位置を確認すると、縮小された画像での座標になることがあります。元の大きさをPillowで確かめ、倍率を掛けてからモザイクの範囲に指定します。倍率を間違えて、的外れな位置にモザイクをかけたことがありました
- **かけた後は必ず目で確認する**：ファイル一覧の名前、表の1列目の名前、帳票の上の社名、住所、電話番号は見落としやすい箇所です
- **加工していることを伝える**：記事の冒頭の定型文で、画面を加工していることを伝えます。画面を1枚も載せない記事では、その文を省きます
- **Windowsのパスの扱い**：bashのヒアドキュメントでWindowsのパス（`\`）をPythonやJavaScriptに渡すと、崩れることがあります。パスを含むスクリプトは、ファイルに書いてから実行します
