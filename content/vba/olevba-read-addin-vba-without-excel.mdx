録画やリボンのボタンを見て「この機能のコードはどれか」を調べたいとき、<Term>Excel</Term>のアドイン（`.xlam`）や`.xlsm`の<Term>VBA</Term>は、そのままでは検索できません。コードは圧縮されて保存されているので、grepでは日本語のメッセージも見つかりません。

Excelで開いて調べる方法もありますが、作業中のアドインに触れてしまいます。ここでは、Excelを起動せずに<Term>Python</Term>の<Term>oletools</Term>でコードをテキストにする方法を説明します。

## 手順の全体像

1. アドインをコピーし、コピーを<Term>ZIPファイル</Term>として展開する
2. `xl/vbaProject.bin`（VBAのコード）と`customUI/customUI14.xml`（リボンの定義）を取り出す
3. `olevba`でモジュールごとのテキストに書き出す
4. ボタンの名前やダイアログの文言でテキストを検索する

元のファイルには一切触りません。使用中のアドインには`~$`で始まるロックファイルがあるので、必ずコピーで作業します。

## リボンのボタンから手がかりを得る

`customUI14.xml`を、リボンに表示されているボタン名（`label`）で検索し、ボタンの`id`と`onAction`を確認します。複数のボタンが同じ`onAction`を共有している場合は、`id`がマクロを特定する手がかりになります。

## VBAをテキストに書き出す

~~~python
import os
import re
import sys

from oletools.olevba import VBA_Parser

src, out = sys.argv[1:3]  # vbaProject.binのコピー、出力フォルダ
os.makedirs(out, exist_ok=True)

vp = VBA_Parser(src)
for (_, _, name, code) in vp.extract_macros():
    if isinstance(code, bytes):
        code = code.decode("cp932", "replace")  # 日本語のコメントや文字列
    name = re.sub(r'[\\/:*?"<>|]', "_", name)
    with open(os.path.join(out, name + ".txt"), "w", encoding="utf-8") as f:
        f.write(code)
~~~

~~~bash
cp MyAddin.xlam work.zip
unzip -o -q work.zip customUI/customUI14.xml xl/vbaProject.bin
PYTHONUTF8=1 python -I extract.py xl/vbaProject.bin src
grep -n "値を切り替えます" src/*.txt
~~~

書き出したテキストはUTF-8なので、日本語の文言でそのまま検索できます。

## Shift_JISのファイルを検索するとき

VBEからエクスポートした`.bas`などのファイルはShift_JISで保存されています。UTF-8の検索語のままでは一致しないため、検索語をCP932に変換してから、バイト列として検索します。

~~~bash
word=$(printf '%s' "値を切り替えます" | iconv -f UTF-8 -t CP932)
LC_ALL=C grep -F "$word" *.bas
~~~

## 注意点

- 他人から受け取ったファイルを調べる場合も、コードは実行されません。ただし、Pythonの実行は`-I`（隔離モード）で行い、調査対象のフォルダにあるファイルを読み込まないようにします
- `olevba`はマクロの不審な処理を検出する機能もあります。詳しくは[oletoolsのリポジトリ](https://github.com/decalage2/oletools)で確認できます
