複数のAI開発チャットを同じフォルダで並行して動かすと、どのチャットが確認待ちなのか分からなくなり、<Term>Git</Term>で共有ファイルを誤ってまとめてコミットする事故も起こります。

この問題は、通知の識別とGitのステージングを別々に対策します。通知はセッションIDを音声へ対応付け、共有ファイルはHEADと自分の変更だけからインデックスを作ります。

## session_idを音声通知へ対応付ける

フックのstdin JSONに含まれる`session_id`をキーにして、チャット名と読み上げ文の対応表をJSONで持ちます。PowerShell側はASCIIだけにし、日本語はUTF-8のJSONへ置くと、Windows PowerShell 5.1の文字コード問題を避けやすくなります。

```powershell
$raw = [Console]::In.ReadToEnd()
$sid = ($raw | ConvertFrom-Json).session_id
$map = Get-Content $mapPath -Raw -Encoding UTF8 | ConvertFrom-Json
$entry = $map.sessions.$sid
if ($entry) {
  Add-Type -AssemblyName System.Speech
  $s = New-Object System.Speech.Synthesis.SpeechSynthesizer
  $s.Speak($entry.stop)
}
```

対応表に無いセッションは既存の通知音だけにします。StopとNotificationで文言を分け、フックは`async: true`にして開発処理を止めないようにします。英字のセッション名をそのまま読ませると不自然なので、読み上げ用のカタカナ名を別に持たせます。

## 共有ファイルはgit addで丸ごと追加しない

worktreeを分けずに並行開発すると、`FEATURES.md`のような共有ファイルへ別チャットの未コミット変更が混ざります。`git add FEATURES.md`を実行すると、関係ない行まで自分のコミットに入ります。

対話操作ができない環境では、HEADの内容へ自分の変更だけを適用したblobを作り、`update-index --cacheinfo`でインデックスへ置きます。

```python
head = subprocess.run(
    ['git', 'show', 'HEAD:FEATURES.md'],
    capture_output=True, check=True
).stdout.decode('utf-8')
updated = head.replace(old_line, new_line)
blob = subprocess.run(
    ['git', 'hash-object', '-w', '--stdin', '--path', 'FEATURES.md'],
    input=updated.encode('utf-8'), capture_output=True, check=True
).stdout.decode().strip()
subprocess.run([
    'git', 'update-index', '--cacheinfo',
    '100644,' + blob + ',FEATURES.md'
], check=True)
```

この方法は作業コピーを書き戻さないため、他チャットの変更は未ステージのまま残ります。コミット前に`git diff --cached FEATURES.md`で自分の行だけが入っていること、`git diff FEATURES.md`で他チャットの変更が残っていることを確認します。

## 運用ルールを先に決める

通知名、共有ファイル、担当チャット、変更依頼の場所をリポジトリへ記録します。新しいチャットを始めるたびにルールを説明するのではなく、共通のREADMEや引き継ぎファイルを先に読ませます。

新規ファイルや自分だけが触るファイルは通常の`git add`で問題ありません。この部分コミット手順は、共有ファイルへ限定して使います。置換対象がHEADと作業コピーにちょうど1つあることを確認してから実行し、曖昧な場合は止めます。

## 文章のルールをpermissions.denyでも補う

Claude Codeでは、`.claude/settings.json`の`permissions.deny`で操作を制限できます。破棄・強制push・全変更のステージングを避ける方針なら、実際に使うシェルごとに設定します。次は出発点になる例で、あらゆる記法を網羅する禁止リストではありません。

~~~json
{
  "permissions": {
    "deny": [
      "Bash(git reset --hard*)",
      "Bash(git push * --force*)",
      "Bash(git push --force*)",
      "Bash(git push * -f *)",
      "Bash(git push * -f)",
      "Bash(git push -f*)",
      "Bash(git add .)",
      "Bash(git add -A*)",
      "Bash(git stash*)",
      "PowerShell(git reset --hard*)",
      "PowerShell(git push * --force*)",
      "PowerShell(git push --force*)",
      "PowerShell(git push * -f *)",
      "PowerShell(git push * -f)",
      "PowerShell(git push -f*)",
      "PowerShell(git add .)",
      "PowerShell(git add -A*)",
      "PowerShell(git stash*)"
    ]
  }
}
~~~

フラグの前後位置や短縮形、利用しているツール名でマッチ結果が変わります。`git stash*`は`git stash list`も止めるため、そのような広さが意図どおりかを確認します。別名や別シェルからの操作まで、短い設定例で完全に防げるとは考えません。[Claude Codeの権限仕様](https://code.claude.com/docs/en/permissions)で利用版のルールを確認します。

試すときは使い捨てリポジトリと読み取り操作・dry-runを使い、止めたい操作が拒否されることに加え、`git status`やファイル指定の`git add`が使えることも確認します。保護対象のファイル読み取りは対応するReadルールも設定します。OSレベルの隔離が必要ならサンドボックスを併用します。

ルールで止まった操作を通すためにエージェント自身が設定を緩めないことも、運用ルールへ明記します。作業ツリーを分けられる場合はGit worktreeによる分離を優先し、共有フォルダ運用では担当ファイルとコミット前の差分確認を続けます。

## まとめ

並行チャット開発では、AIが別チャットの作業を自動で理解していると考えないことが重要です。セッションIDを使った通知、共有ファイルの部分コミット、リポジトリ内の引き継ぎ資料を組み合わせると、同じ作業フォルダでも確認漏れと誤コミットを減らせます。
